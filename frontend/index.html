SECTION A-A how the estimate is made

RMSE · FD001 OFFICIAL TEST SET
MODELRMSE
Babu et al. 2016, CNN18.45
Ridge regression, this project's baseline17.47
Zheng et al. 2017, deep LSTM16.14
XGBoost + rolling features, this project15.85
  1. 100 engines run to failure, 20,631 training cycles, 14 informative sensors after dropping 7 near-zero-variance channels.
  2. Splits are grouped by engine, never random. A random split leaks the same engine into train and test and the model memorizes drift instead of learning degradation.
  3. Features are rolling means and standard deviations over 30-cycle windows. The window length was chosen to span roughly one HPC fouling cycle, not tuned by grid search.
  4. I capped RUL at 125 cycles per the standard piecewise-linear convention.
  5. Attribution uses XGBoost's native pred_contribs, exact TreeSHAP. The top feature, sensor_3_mean30 (30-cycle mean of HPC outlet temperature), is the thermodynamic signature of compressor fouling: efficiency drops, outlet temperature rises, remaining life shortens.
  6. Transformer and hybrid papers published since have pushed FD001 lower. 15.85 is a strong classical result, not the current state of the art.

GENERAL NOTES

  1. This demo calls the live model over the live API. Nothing on this page is staged output.
  2. The specimen engine is synthetic, generated in the browser in the shape of FD001 telemetry (50 cycles, drifting toward failure). It exists so the demo can run without a dataset on hand, and it is labeled every place it appears.
  3. The band around each estimate is ±15 cycles, clipped to 0..125. It is a heuristic, not a formal prediction interval; the API schema says the same.
  4. The API sleeps between visitors on Render's free tier. The first request boots the container, 30 to 60 seconds. The page shows real elapsed time while that happens.
